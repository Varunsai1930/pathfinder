## 1. Pitch

Pathfinder is a personalized learning-path recommender that answers "which tech role should I aim for, and what exactly do I do next?" with a **conversational front door and a deterministic engine**: the learner describes their goal in plain English, an LLM drafts their profile (interests, skills, constraints) as *editable suggestions* — or honestly declines when the goal lies outside the six supported paths — and a fully transparent scoring engine (55% RIASEC interest similarity / 35% tiered skill readiness / 10% work-style, all cosine-based) ranks six entry-level roles with visible score math and exact skill gaps. The chosen path becomes a five-milestone roadmap dashboard with a prerequisite-aware 19-course catalog, time/quiz telemetry, a feedback loop that promotes demonstrated skills into the profile (which invalidates and recomputes cached results), a grounded Q&A assistant that quotes the learner's own goal, and a dedicated progress page with completion, hours, and next-action tracking. The architectural thesis: **"The AI can persuade. It can't decide."** — the LLM is structurally incapable of inventing a role, milestone, or skill because every response is schema-validated and ID-checked against the learner's own computed data, with a deterministic fallback on every failure path.

## 3. How the AI actually works

### Deterministic core (no LLM, fully reproducible)
- **Matching** (`backend/app/matching/service.py`): answers normalized into a 6-dimension RIASEC vector + 5-axis work-style vector; each of the **six** roles has a stored target profile; similarity is **cosine** (magnitude-invariant — an earlier magnitude bug was fixed and pinned by `tests/test_matching_invariance.py`). Skill readiness uses `CONFIDENCE_WEIGHTS {none:0, aware:0.3, practised:0.7, project-ready:1.0}` × `TIER_WEIGHTS {core:1.0, supporting:0.5, optional:0.25}`; final fit = 55/35/10 blend. Confirmed vs missing core/supporting skills derive from the same data (zero overlap, tested).
- **Timeline feasibility is computed in code, never by the model** (`_timeline_facts`, `personalization.py:284-291`): total milestone hours ÷ hours-per-week vs target weeks.
- **Six-role calibration is regression-tested**: `tests/test_matching_representative.py` builds one representative profile per role — including the new Security Analyst and Data Engineer profiles — and asserts each ranks its intended role #1 (parametrized ids `frontend…data-engineer`, lines 114-131); `test_catalog.py` pins the six-role list, 5-milestone structure, O*NET references, and taxonomy coverage.

### LLM layer (optional, constrained, pinned)
- **Model:** `meta-llama/llama-3.1-8b-instruct:free` via OpenRouter, **pinned** for reproducibility (`backend/app/config.py:22`); called through the OpenAI SDK with `temperature=0.1`, `max_tokens=4000`, 25 s timeout (`personalization.py:147-190`).
- **Structured output only:** every call uses `response_format json_schema strict` with Pydantic schemas that have `extra="forbid"`.
- **Four constrained uses:** (1) intake extraction → RIASEC dimension hints 0-100 + skill hints + constraints + a `supported_path` classification; deterministic code maps hints to the 1-5 answer scale (`_hint_to_response`) — the model never touches individual answers; (2) match fit explanations; (3) roadmap personalization (fit explanation, 5× weekly focus, adaptation note); (4) grounded Q&A.
- **Validation & grounding guardrails:** unknown/duplicate role or milestone IDs → fallback (`personalization.py:250-254, 463-466, 616-620`); Q&A answers may cite only owned role/milestone IDs; intake skill hints outside the 19-skill taxonomy are dropped (741-747); goal text is treated as untrusted data (prompt-injection guard, 608-610).
- **Honesty detectors (the standout engineering):** a regex **skill-attribution detector** (`_ATTRIBUTION_RE`, lines 41-64, applied at 341-356) rejects prose claiming skills/traits the learner never confirmed (e.g. "your analytical mindset" with zero confirmed skills → whole response replaced by deterministic fallback; heavily tested in `test_personalization.py:425-531`); a **timeline-honesty check** (316-323, 474-481) rejects LLM prose that asserts an infeasible plan fits when computed `weeks_needed > target_weeks`.
- **Fallbacks everywhere:** missing key, timeout, rate limit, malformed JSON, schema failure, or any validation miss → deterministic template content with `generation_mode: "fallback"`. The Q&A fallback quotes the learner's stored goal and names concrete next milestones (`fallback_question_answer`, 519-536). The README documents how to verify the live LLM path (`"generation_mode": "llm"`).

### Persisted match cache (new)
- `POST /match` computes, then **persists the result into the previously-unused `recommendations` table**, stamped with the profile row's `updated_at` (`api.py:76`, `match_store.py:27-74` — best-effort; a persistence failure never fails the request).
- `GET /match` serves the persisted result **only when the stamp matches the current profile version**, else **404** with an explicit instruction to POST once (`api.py:80-103`, `match_store.py:102`). Reassessment **and feedback-loop skill promotions** bump `profiles.updated_at` (`task_store.py:139, 174`), so stale results are never silently served.
- Frontend honors the protocol: Results loads GET-first and only POSTs on 404/405 (`ResultsPage.tsx:125-151` — the 405 branch covers older backend builds during mixed-version deploys); the landing top-path card (`LandingPage.tsx:48-55`) and the progress page (`ProgressPage.tsx:81-84`) do the same. Tests: `test_match.py` (persisted-without-recompute, stale-after-resubmission, 404-when-never-computed).

### Non-LLM adaptation loop
Completing a milestone persists optional telemetry (`time_spent_minutes` 0-10080, `quiz_score` 0-100, validated in `task_store.py:337-340`) and **promotes that milestone's skills to "practised" in the learner's profile** (`task_store.py:99-186`) — a genuine feedback loop: the next `/match` changes, and the cached result is invalidated by the same `updated_at` bump. `_telemetry_summary` (189-219) and the adaptive next-action hint (291-316) use the same data (quiz avg < 60% → "review fundamentals"; avg time > 180 min → "smaller blocks").

## 5. Innovation & differentiation

1. **Auditable match math.** Learners see the component scores and weights on every card; surveyed competitors don't expose scoring (positioning scan in `docs/uniqueness_report.md`). Landing headline: "The AI can persuade. It can't decide."
2. **Hybrid deterministic-core + validated-LLM architecture.** The LLM only explains and personalizes prose; it cannot create or alter a course, milestone, or skill — schema + ID checks + honesty detectors + deterministic fallback on every path.
3. **Honesty engineering as a feature** — attribution and timeline-mismatch detectors that reject flattering-but-ungrounded prose (`personalization.py:41-74, 316-356, 474-481`) are rare even in production LLM apps, and each detector has dedicated tests.
4. **Grounded Q&A over the learner's own results — including their own stated goal** — the system prompt forbids outside knowledge and must say when the data cannot answer; the goal is quoted as data, with an explicit injection guard.
5. **Decline-don't-fabricate intake** — most tools force-fit any goal; Pathfinder classifies the goal against its six supported paths and refuses to pre-fill when it's out of scope, telling the learner exactly what it does cover.
6. **Closed adaptation loop with cache invalidation** — telemetry → skill promotion → changed recommendations; the persisted-match protocol (version stamps, 404-on-stale, one recompute) shows real cache-consistency thinking.
7. **Scope discipline** — six deeply curated roles (RIASEC vectors, O*NET-referenced `onet_soc_code`/`onet_reference_url`, 5 milestones, portfolio briefs each) over thousands of shallow ones; the résumé/GitHub enrichment idea was deliberately cut (documented in `PLAN.md`, `docs/uniqueness_report.md` §6 — the now-unused `enrichment_events` table is the visible leftover, see §7).

## 8. Suggested demo flow (6 steps)

1. **Landing → conversational intake.** Sign in (seeded OTP account), start the assessment, paste a natural-language goal ("second-year student, enjoys building small web pages and digging through spreadsheet data, 10 hrs/week, job-ready in six months"), click *Pre-fill my assessment* — show the drafted assessment and **edit one answer on camera** ("the learner, not the model, has the final word").
2. **Decline, don't fabricate (optional contrast).** Back to step 1 with an unsupported goal ("I want to become a nurse") — Pathfinder declines the pre-fill, shows no invented scores, and names the six supported paths with how to retry (`AssessmentPage.tsx:362-366`).
3. **Results with visible math + goal-aware chat.** Submit; show the six ranked cards, 55/35/10 breakdown bars, skill gaps. Open the floating chat and ask "What did I write as my goal?" — it quotes the learner's own intake words; then type "thanks" — a brief conversational reply, no model call (badge flips to `Pathfinder chat`).
4. **Dashboard + feedback loop.** Explore the top path; check a milestone complete with time=180 min and quiz=70% — show the NEXT BEST ACTION banner change, the skill-promotion toast, and learning-pattern stats; scroll to *Courses for your gaps* and the prerequisite met/missing chain.
5. **Progress page.** Return home, click **"Track my progress"** on the top-path card — the completion ring, planned-vs-done hours, logged time (3h 0m), the "next thing to do" card, and the completed/remaining lists; note it follows the path actually explored, not just the top match.
6. **Close on the differentiator.** Back on landing: the hero now reads **"Continue my path — {role} →"** and results load instantly from the persisted match (GET-first cache; a fresh compute happens only once per profile version). One-liner: "Every other tool tells you what to learn. Pathfinder shows you the math, then explains it in plain language — the AI can persuade, but it can't decide."
